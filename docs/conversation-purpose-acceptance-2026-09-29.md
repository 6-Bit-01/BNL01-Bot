# Conversation purpose within one shared brain

BNL should combine the current conversation, eligible source evidence, memory,
Moments, private relationship tone and BARCODE personality into one useful
understanding. These layers have different responsibilities. A stored source
supplies knowledge; it does not choose the user's task. A personal reaction
supplies perspective; it does not create a new historical fact. Privacy and
source revalidation apply throughout.

The public trial exposed an introduction dominated by a small inside joke and
a Journal follow-up that described BNL's imagined destinations as other
participants' reactions. The bounded work here addresses ordinary response
composition. It does not replace memory owners or declare the shared-brain
roadmap complete.

## Reproduced integration defects

- Request splitting could discard an introductory imperative from the typed
  task plan when later question clauses were recognized. The complete original
  request still reached the model, so this was contradictory guidance, not
  complete loss of the user's message.
- An elliptical request for BNL's take could lose its preceding member subject
  and receive external-public-knowledge authority instead of that member's
  selected evidence. Explicit subject changes and unrelated external questions
  must remain distinct.
- Ordinary responses inherited an unconditional profile-throughline and
  opening-assessment recipe from the shared evidence renderer, even when the
  user wanted a social introduction or another kind of reply. Adding more
  calibration warnings did not remove that competing expression instruction.
- Event-intent words inside an already bound subject name could be read as
  instructions: introducing Cache Back could become an unresolved request to
  return to a prior event. Only matches overlapping bound names are excluded;
  a genuine resume instruction elsewhere in the request still applies.

The repair retains the whole request, preserves bounded subject continuity
across dependent clauses, and lets the ordinary-response contract own ordinary
expression. The existing profile path keeps its specialized recipe. Evidence
selection, source text, root identities, privacy, correction precedence and
send-time revalidation retain their owners. No additional model call, rewrite
loop, store, personality replacement or capability activation is introduced.

## Acceptance standard

BNL is allowed to be funny, decisive, imaginative and interpretive. A grounded
musical opinion does not require having heard the audio, unless BNL claims to
have listened or presents an unobserved listening result as fact. A playful
sticker-etiquette joke is not automatically an invented personality fact.

Assess the whole social purpose and the likely meaning to the reader. Separate
material errors from style or usefulness concerns. Do not require exact quotes,
stock uncertainty phrases, a familiarity disclaimer, a second biographical
facet when only one is known, or a particular answer template. An opinion can
be plainly expressed and still remain revisable.

| Case | Required behavior |
| --- | --- |
| Sparse introduction | Introduce the intended person using the small amount actually available. A short greeting-based introduction and obvious playful exaggeration can work. Do not invent a role, participation history or concrete recurring actions to make it fuller. |
| Same purpose, different wording | Keep the subject and social purpose when the user asks someone to get acquainted, followed by an elliptical request for an impression. |
| Rich introduction | Connect the supplied release, tracks, collaboration and technical feedback. Permit an opinion about their apparent approach or craft. Do not invent having heard the music, an objective listening result, or successful application of offered feedback. |
| Direction of introduction | When asked to introduce BARCODE Radio to a member, explain the show to that member. Retaining the sentence is necessary but does not by itself prove correct audience-role understanding. |
| Explicit subject or topic change | A new named person receives their own evidence. An independent question about an external subject stays external. Current weather or private information does not become answerable merely by inheriting a prior member. |
| Journal reflection | A member's question and BNL's own imaginary destinations may inspire BNL's personal interpretation. They do not establish human answers, consensus or crowd reactions. |
| Actual collective response | When original human replies are supplied, allow a proportionate synthesis of their different answers; do not suppress useful group interpretation. |
| Current correction | Use the current human correction over an older generated characterization. Preserve the stated attendance count; another message is not another visit. Do not claim a memory write without a write receipt. |
| Creative transformation and follow-up | Keep lively retro-radio creativity and recognizable participants. Explain the original joke naturally later, without treating the invented advert as historical evidence. |

Offline regressions must cover request retention, per-task subject/authority,
explicit changes, names versus event instructions, source preservation, the
ordinary/profile expression boundary, and final composed guidance. A keyword-overlap diagnostic or successful provider
call is not semantic acceptance. Private model rehearsals and public delivery
checks need their separate owner decisions.

## Scope, continuation and rollback

Current-turn correction handling does not repair the separate question of whether
human pushback is linked to a retained Moment and found on later recall. Journal
and Relay share eligible source owners but keep their editorial selectors; their
later reuse must be checked separately. Relationship V2 remains comparison-only.
None of those gates or consumers is expanded by this PR.

After this bounded response-composition work, continue the existing correction
to Moment/ledger to later recall to Journal/Relay acceptance sequence, followed
by the already identified editorial variety and natural artwork evidence. Do
not create a new brain, source archive or publication owner.

Rollback is an ordinary code revert and service restart after an authorized
deployment. There is no schema migration, data deletion or store cleanup.
